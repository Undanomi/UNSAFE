# 画面設計一覧

## 目的

本ディレクトリは、画面ルーティングおよび各画面の実装方針を定める。画面ごとの要件は Issue #21〜#25 を基にする。

認証認可の詳細・API エンドポイント・リクエスト／レスポンス型・データベース設計は本ドキュメントの対象外とする。認証認可の正本は[認証方針](../auth-spec.md)とする。各ページには、画面が必要とする表示データと利用者操作の結果のみを記載する。

## 認証と共通遷移

- `/machines`、`/machines/[machineId]`、`/machines/chat`、`/machines/chat/[sessionId]`、`/profile`、`/users/[userId]` は認証必須とする。未認証でアクセスした場合は `/login` へ遷移する。
- 認証済みで `/login` を開いた場合は `/machines` へ遷移する。
- `/privacy` は認証状態によらず表示できる。ログイン画面から遷移できる。
- ログイン成功後は `/machines` へ遷移する。
- 一覧からマシンを選択した場合は `/machines/[machineId]` へ遷移する。
- 一覧で作成者を選択した場合は `/users/[userId]` へ遷移する。
- 一覧の「マシン作成」から `/machines/chat` へ遷移し、新規チャットを直接表示する。サイドバーで既存セッションを選択した場合は `/machines/chat/[sessionId]` を表示する。
- サイドバー下部のアカウント設定メニューで「ログアウト」を選択した場合は、セッションを破棄して `/login` へ遷移する。
- チャットでマシン生成・ビルドを開始し、対象マシンを特定できる状態になった場合は `/machines/[machineId]` へ遷移する。
- 詳細画面および公開プロフィール画面（`/users/[userId]`）の「戻る」は `/machines` へ遷移する。自分のプロフィール（`/profile`）には戻る導線を表示しない。

## 実装上の共通方針

- 認証後の画面は、マシン作成・マシン一覧・プロフィール・チャット一覧トグルを置く固定サイドバーとメインエリアで構成する。サイドバー下部にはプロフィール導線と、ログアウトを含むアカウント設定メニューを置く。背景は白基調とし、黒基調の操作コンポーネントとニューモーフィズムの陰影を共通デザインに用いる。
- 初期表示に必要なデータは Server Component で取得し、入力・選択・送信・表示中の状態は Client Component で扱う。
- 更新操作は Server Action を経由し、ポーリングやダウンロードなど HTTP の制御が必要な操作は Route Handler を経由する。
- 各画面は、読み込み中、データなし、操作中、失敗、権限なしまたは対象なしの状態を表示できるようにする。
- 業務データの正本や外部サービスへの接続方法は、画面コンポーネントに持たせない。

## 実装済み機能とモックの範囲

Google SSO、Firebase Session Cookie、認証必須ルートの保護、ログアウト、PostgreSQLへの初回ユーザー作成、プロフィール、マシン、チャット、AI・ビルドサービスとの通信およびファイルダウンロードは実装済みとする。公開プロフィール画面のマシン・回答履歴には一部モックデータが残る。

動的ルートの `/machines/[machineId]`、`/machines/chat/[sessionId]`、`/users/[userId]` は `loading.tsx` を置き、遷移中は共通の読み込み表示を出す。

マシン作成チャットの一覧と途中再開は、BFF がPostgreSQLへ作成・保存するセッションを正本とする。新規チャットはマシン名確定後に保存し、会話状態の保存にブラウザの永続ストレージは使用しない。

## ドキュメント更新方針

- 画面の URL、遷移、アクセス条件、表示項目、利用者操作を変更する実装では、対応するページ設計書を同じ変更で更新する。
- ページの追加・削除・URL変更を行う場合は、本書の画面一覧、共通遷移、対応 Issue の記載も更新する。
- モックを更新した場合は、影響するページ設計書を確認し、モックとの差分が残る場合は理由を記載する。
- 未確定または延期した機能は削除せず、対象ページに状態、理由、再検討条件を明記する。
- API 契約や認証方式など別設計書が正本となる事項は、画面設計書に詳細を重複して書かず、画面への影響だけを記載する。
