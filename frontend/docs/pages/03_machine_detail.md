# マシン詳細画面

## 基本情報

| 項目 | 内容 |
| --- | --- |
| 対応 Issue | [#22: フロント／マシン詳細画面の機能設計](https://github.com/Undanomi/SLSG/issues/22) |
| ルート | `/machines/[machineId]` |
| アクセス条件 | 認証必須。対象マシンを閲覧できない場合は、権限なしまたは対象なしの状態を表示する。 |
| 目的 | マシンの情報を確認し、フラグ回答、成果物ダウンロード、誘導問題作成を行えるようにする。 |

## 表示要素

- マシン一覧と同じ構成の、アイコン・マシン名・取得した概要からなるページ見出し
- 見出しの右側に置く「ダウンロード」ボタンと「誘導問題」ボタン
- マシン説明カード。説明文、公開範囲、難易度、テーマ、作成者、作成日を表示する。
- ユーザーフラグ入力欄と判定ボタン
- システムフラグ入力欄と判定ボタン
- 各フラグの解答状態と判定結果
- 「ダウンロード」ボタン。ダウンロード可能な状態でのみ実行可能にする。
- ビルド中の進捗、完了、失敗状態を表示するビルド状態領域
- 所有するマシンのビルドが失敗した場合に表示する「もう一度ビルドする」ボタン
- 「誘導問題」ボタン。初回作成後は「誘導問題を再生成する」に変わる。
- シナリオと実際のプロビジョニング用コードに基づく、フラグ別・縦並びの誘導問題と任意表示のヒント
- マシン一覧へ戻る導線

## 操作と遷移

| 操作 | 結果 |
| --- | --- |
| 戻る | `/machines` へ遷移する。 |
| ユーザーフラグを送信 | 判定結果と回答済み状態を更新する。 |
| システムフラグを送信 | 判定結果と回答済み状態を更新する。 |
| フラグ入力欄で Enter を押す | 判定を送信しない。判定は明示的に「判定する」ボタンを選択した場合だけ実行する。 |
| ダウンロードを選択 | ブラウザで成果物のダウンロードを開始する。ダウンロード方式は成果物ダウンロード設計に従う。 |
| もう一度ビルドする | AI サーバーの既存セッションを再実行し、失敗したソースの修復とビルドを開始する。 |
| 誘導問題を作成 | 誘導問題の作成を開始し、完了後に結果を表示する。 |
| 誘導問題を再生成 | 現在のユーザーの取得済みフラグを再評価して、保存済み内容を置き換える。 |
| ヒントを表示 | 各誘導問題のMarkdown形式のヒントを独立して開閉する。確認済みの内容は表示したままにする。 |
| 確認して次へ | 現在の問題を確認済みにし、次の問題を同じ縦並びへ追加表示する。 |

## 画面状態

| 状態 | 表示・操作 |
| --- | --- |
| 読み込み中 | 詳細領域に読み込み中の表示を出す。 |
| ダウンロード可能 | ダウンロードボタンを有効化する。 |
| 生成・ビルド中 | AI サーバーの状態を定期取得し、処理段階と進捗率を表示する。ディスクイメージ変換中は80%と専用メッセージを表示する。ダウンロードとフラグ回答は無効化する。 |
| ビルド完了 | AI がシナリオ生成時に作成した、攻略のネタバレを含まないプレイヤー向け紹介文をマシン説明として表示する。 |
| ビルド失敗 | 失敗状態を表示する。内部エラーの詳細は表示せず、所有者にだけ再ビルド操作を表示する。 |
| フラグ未回答／不正解／正解 | 入力欄と判定結果を状態に応じて表示する。正解後も他方のフラグは独立して回答できる。 |
| 対象なし・権限なし | 詳細情報やフラグを表示せず、一覧へ戻る導線を提示する。 |
| 誘導問題作成中・成功・失敗 | 誘導問題 UI の領域内で状態を表示し、失敗時は再実行できるようにする。 |

## 誘導問題作成 UI の扱い

誘導問題は、ページ見出しの右端に置く独立した操作ボタンとして実装する。生成結果はユーザーとマシンの組み合わせごとに保存し、再生成操作までは同じ内容を表示する。他ユーザーの結果とは共有しない。

回答の自動正誤判定は行わない。侵入経路には同じ目的を達成できる表現ゆれや別解があり、自由記述をAIで判定すると正しい調査を誤って不正解にする可能性があるためである。HTBのretiredマシンに近い縦並びとし、User flagまでの項目はUser flag入力欄の直前、System flagまでの項目はSystem flag入力欄の直前に置く。最初は各区分の先頭だけを表示し、「確認」で次を開示する。確認済みの項目は消さず、必要な場合だけ各ヒントを開ける。User flagが存在する場合、System flag側の誘導はUser flag正解後に開放する。

## 実装時の責務

- 初期表示でマシンの表示情報とフラグ回答状態を取得する。
- 生成・ビルド中は BFF の Route Handler を通じて AI サーバーのセッション状態を定期取得し、PostgreSQL の `machines` と `chat_sessions` に同期する。
- ビルド成功時に AI サーバーの `scenario_description` をPostgreSQLのマシン説明へ同期する。旧プレースホルダーが残るビルド済みマシンは、詳細表示時に一度だけ補正する。
- 再ビルドは所有者だけが Server Action から要求できるようにし、AI サーバーの `POST /v1/sessions/{session_id}/machines` をシナリオ ID なしで再実行する。
- PostgreSQLに正解値が保存されているフラグだけを表示し、回答は Server Action からサーバー側で判定する。クライアントへ正解値を渡さない。
- フラグ送信ごとに、該当する入力欄の送信中と正解・不正解だけを独立して扱う。内部エラーの詳細は表示せず、入力欄で Enter を押しただけでは送信しない。
- フラグの正解値、ダウンロード URL、誘導問題の生成方式は画面に持たせない。
- フラグ取得履歴はユーザー／システムの種別ごとに保存し、誘導問題の生成時に取得済み目標を除外する。
- 誘導問題はAIサーバー内の確定済み攻撃グラフと生成ソースを根拠にし、正解フラグ値が出力へ含まれないことを検査する。
