## 認証方式

現時点ではメールアドレス・パスワードによるログインと新規登録を画面例として記載する。ただし、Google アカウントを利用した OAuth ログインまたは新規登録を採用する場合がある。最終的な認証方式、利用可能なログイン手段、アカウント連携の扱いは認証設計の正本で確定する。

### 検討方針

ID・パスワード登録は、認証基盤の導入・運用コストに加え、パスワードの安全な保管、再設定、認証失敗時の対策などのセキュリティ上の負担が大きいと考えている。低コストでこれらを満たす実装方法を採用できない場合は、前年の実績を踏まえ、Google ログインのみのパスワードレス認証を採用する。

この方針を採用する場合は、メールアドレス・パスワード入力、新規登録への切り替え導線および新規登録ボタンを削除し、本設計書の表示要素・操作・画面状態を同じ変更で更新する。

Google OAuth を採用する場合は、「Google でログイン」ボタンから認証プロバイダーへ遷移し、認証完了後は `/machines` へ戻る。認証キャンセルまたは失敗時は `/login` に留まり、再試行できるようにする。

## 表示要素

- サービス名またはタイトル
- メールアドレス入力欄
- パスワード入力欄
- ログインボタン
- 新規登録への切り替え導線
- 新規登録時のメールアドレス、パスワードの入力欄
- 新規登録ボタン
- Google OAuth を採用する場合の「Google でログイン」ボタン
- プライバシーポリシーへのリンク
- 認証失敗時に表示する共通エラーメッセージ

パスワードは伏せ字で表示し、ブラウザのパスワード入力として扱う。メールアドレスの存在有無やパスワード誤りの詳細は画面に出さない。

## 操作と遷移

| 操作 | 結果 |
| --- | --- |
| メールアドレスとパスワードを入力して送信 | 入力を検証して認証を要求する。成功時は `/machines` へ遷移する。 |
| 「新規登録」を選択 | 新規登録用の入力欄と送信ボタンを表示する。 |
| 新規登録情報を入力して送信 | 入力を検証してアカウント作成を要求する。成功時は `/machines` へ遷移する。 |
| 「Google でログイン」を選択 | Google OAuth を採用する場合に認証プロバイダーへ遷移する。認証成功後は `/machines` へ遷移する。 |
| 「プライバシーポリシー」を選択 | `/privacy` へ遷移する。 |
| 認証失敗 | 画面遷移せず、共通エラーを表示する。パスワードの値は再表示しない。 |
| すでに認証済みでアクセス | `/machines` へ遷移する。 |

## 画面状態

| 状態 | 表示・操作 |
| --- | --- |
| 初期 | 入力欄とログインボタンを表示する。 |
| 新規登録 | メールアドレスとパスワードの入力欄、新規登録ボタンを表示する。 |
| 入力エラー | 必須入力などのエラーを該当入力欄の近くに表示する。 |
| 送信中 | 二重送信を防ぐためログインボタンを無効化する。 |
| OAuth 認証中 | Google の認証画面へ遷移する。キャンセルまたは失敗後はログイン画面で再試行できる。 |
| 認証失敗 | 共通エラーを表示し、再入力・再送信できるようにする。 |
| 認証済み | マシン一覧へ遷移する。 |

## 実装時の責務

- ログイン状態の確認は画面表示時に行う。
- フォームの入力状態、入力エラー、送信中の状態は Client Component で扱う。
- メールアドレス・パスワード方式と Google OAuth のどちらを採用するかは未確定とし、認証設計の確定に合わせて表示要素と操作を更新する。
- 認証・セッション作成の詳細、Cookie の内容、認証基盤との通信方式は認証設計の正本に従う。
