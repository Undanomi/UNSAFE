# マシン一覧画面

## 基本情報

| 項目 | 内容 |
| --- | --- |
| 対応 Issue | #24（機能設計）、#34（DB 接続） |
| ルート | `/machines` |
| アクセス条件 | 認証必須。未認証の場合は `/login` へ遷移する。 |
| 目的 | 公開済みマシンを探し、詳細表示または新規作成を開始する。 |

## 表示・操作

- テーブル形式で、マシン名、タグ、難易度、回答状態、作成者、作成日の列を表示する。マシン名の下に概要を補足表示する。
- 作成者の頭文字アイコン・名前、作成日（日本時間）を表示する。内部 ID は一覧に表示しない。
- 狭い画面ではテーブル部分を横スクロールして閲覧する。
- マシン名から `/machines/[machineId]`、作成者名から `/users/[userId]` へ遷移する。
- 「マシン作成」から `/machines/chat` へ遷移する。共通サイドバーにプロフィールへの導線を置く。
- キーワード、難易度、自分が作成したマシン、回答状態を組み合わせて検索する。
- 検索ボタンで条件を適用し、1 ページ目に戻る。条件リセットは並び順も初期値に戻す。
- 1 ページ 10 件。総件数と表示範囲を表示し、テーブル下には 1 ページだけの場合も現在ページと前後ページの操作を表示する。ページ番号は先頭・末尾・現在ページとその前後を表示し、離れた範囲は「…」で省略する。現在ページは黒背景・白文字、他ページは白背景の角丸枠とし、前後移動は矢印で表示する。移動できない方向は無効表示にする。0 件の場合はページネーションを表示しない。

## URL クエリ

| パラメーター | 値・既定値 |
| --- | --- |
| `page` | 1 始まりの整数。未指定・不正値・重複指定は 1。総ページ数を超える場合は最終ページへリダイレクトする。 |
| `q` | 前後空白を除いた最大 100 文字。マシン名・タグのいずれかに部分一致（英字は大文字小文字を区別しない）。 |
| `level` | `easy` / `medium` / `hard` をセレクトボックスで1つ選択。`?level=medium` のように URL に保持する。未選択はすべて。表示名は既存詳細画面に合わせ Easy / Medium / High。 |
| `owned` | `1` の場合は自分が作成したマシンのみ。それ以外は公開済みマシンと自分が作成したマシン。 |
| `solved` | `yes`（回答済み）/ `no`（未回答）。それ以外はすべて。 |
| `sort` | `desc`（新しい順、既定値）/ `asc`（古い順）。作成日時が同じ場合は ID 昇順で安定させる。 |

ページ移動時にすべての適用済み条件を保持する。URL の再訪問・再読み込み・ブラウザーの戻る／進むでも同じ条件を復元する。

## 検索条件の組み合わせと適用箇所

| 条件 | 適用箇所 | 判定 |
| --- | --- | --- |
| 削除状態 | Firestore クエリ | 通常一覧は削除以外の有効な状態を `in` で指定し、検索時は `status != deleted`。公開・非公開や所有者にかかわらず削除済みは取得しない。 |
| 公開状態・所有者 | Firestore クエリ | 通常は「公開済み OR 自作」。「自分が作成したマシンのみ」を指定した場合は自作だけ。 |
| キーワード | 取得後のサーバー処理 | 名前またはいずれかのタグに、キーワード全体が部分一致する。概要・説明文・作成者名は検索対象外。 |
| 難易度 | 取得後のサーバー処理 | 選択した1つの難易度に一致する。未選択なら制限しない。 |
| 回答状態 | 取得後のサーバー処理 | ログインユーザーの回答履歴に基づいて回答済み・未回答を判定する。未指定なら制限しない。 |
| 作成日順・ページ | 通常一覧は Firestore クエリ、検索時は取得後のサーバー処理 | 通常一覧は DB 側で整列して最大 10 件を取得する。検索時は候補全件に検索条件を適用してから整列し、指定ページの最大 10 件を返す。 |

削除状態、公開状態・所有者、キーワード、難易度、回答状態の各条件は AND で組み合わせる。「公開済み OR 自作」、名前・タグの一致、複数の難易度は、それぞれの条件内で OR とする。

キーワードは前後の空白を除き、大文字小文字を区別せずに照合する。複数の単語を空白で分割する検索や、全角・半角、ひらがな・カタカナの表記ゆれ吸収は行わない。たとえば `SQL` は名前の `sql-lab` に一致するが、`SQL Linux` はその文字列全体を含む名前または単一のタグだけに一致する。空文字ならキーワードで絞り込まない。

通常の一覧には他人の公開マシンと自作の公開・非公開マシンを含める。他人の非公開マシンと削除済みマシンは検索条件に一致しても含めない。`ready` のみを対象にする条件はなく、自作のビルド中・失敗したマシンも削除済みでなければ対象になる。

例：`/machines?q=sql&level=easy&level=medium&solved=no&owned=1&sort=asc` は「削除されていない自作マシン」から、「名前またはタグに sql を含む」「Easy または Medium」「自分が未回答」のすべてを満たすものを古い順に表示する。総件数はこれらの条件をすべて適用した後の件数。

`level` 以外のパラメーターを複数指定した場合は、そのパラメーターを未指定として扱う。未対応のパラメーターは無視する。

## DB 契約と取得責務

- セッション Cookie を検証した利用者 ID をサーバーの一覧サービスへ渡す。クライアントから所有者 ID を受け付けない。
- Firestore `machines` は DB の取得条件で「削除されていない」かつ（`published == true` または自分が作成したもの）に絞る。所有者判定では `created_by == users/{uid}` または UID 単体との一致を確認する。`owned=1` の場合は公開済みという条件を外し、自分が作成したものだけを DB から取得する。
- Firestore ドキュメント ID を正とする。`status` は必須で、フィールドが存在しないドキュメントも取得対象外。通常一覧は `created`, `building`, `ready`, `failed`, `preparing` を `in` で指定し、削除状態の不等値条件による並び順の制約を避ける。状態を追加するときは一覧サービスの有効状態も更新する。
- `machines.created_at` は `Date.toISOString()` が返す UTC・ミリ秒固定の文字列（例：`2026-09-20T01:23:45.000Z`）で保存する。DB の文字列順と実日時順を一致させるため、タイムゾーン表記や Timestamp 型を混在させない。アプリのマシン作成処理とデータ投入スクリプトもこの形式を使用する。
- 一覧取得では `name`, `summary`, `description`, `tags`, `level`, `created_at`, `created_by`, `published`, `status` だけを取得する。`description` は一覧の説明表示に使用し、空なら `summary` を使う。フラグ正解値・成果物パス・AI セッション ID は読み出さない。
- 回答済みは `users/{uid}.solved_machines` の `machines/{machineId}` との一致で判定する。現契約はフラグ別の進捗を持たないため、いずれか 1 つのフラグに正解した時点で回答済みとする。不正解や空回答は保存しない。
- 正解時はサーバー側のフラグ判定サービスで `arrayUnion` を使って記録し、一覧を再検証する。重複回答や同時回答でも既存記録を上書きしない。フラグを持たないマシンは、既存の回答済み記録がなければ未回答になる。
- 表示ページの作成者だけをまとめて取得し、存在しない作成者は「ユーザー」と表示する。
- 一覧から移動した詳細が同名 ID のダミーデータにならないよう、詳細取得も DB を正とする。

### ページングの実現方法と制約

通常一覧と検索・絞り込み時で取得処理を分ける。削除済み・公開状態・所有者の条件は、どちらでも必ず DB 側で適用する。

| 取得モード | 条件 | DB から取得するマシン |
| --- | --- | --- |
| 通常一覧 | 正規化後の `q` が空、`level` が未選択、`solved` が未指定、`owned` が false | 日時順で対象ページの最大 10 件。`page` や `sort` だけの変更もこのモード。 |
| 検索・絞り込み | `q`、`level`、`solved`、`owned` のいずれかが指定されている | DB の公開状態・所有者・削除条件を満たす候補全件。サーバーで残りの条件を適用し、整列して最大 10 件を表示する。 |

通常一覧は `created_at` を指定方向、ドキュメント ID を昇順に並べる。総件数は同じ取得条件の `count()` 集計で求め、ページ番号を有効範囲に補正してから `offset((page - 1) * 10).limit(10)` で取得する。総件数のためにマシン本文を全件取得しない。0 件ならページは 1、最終ページを超える指定は最終ページへリダイレクトする。件数集計とページ取得は別リクエストのため、その間に追加・削除があれば件数と表示が一時的にずれる場合がある。

既存のページ番号・先頭／末尾への移動を維持するため、通常一覧は offset 方式を採用する。サーバーに返るマシン本文は最大 10 件だが、Firestore では読み飛ばしたドキュメントも読み取り対象になる。たとえば 2 ページ目は 10 件を読み飛ばして最大 10 件を返すため、マシンのドキュメント読み取りは最大 20 件であり、常に 10 件分の読み取り課金に収まるわけではない。さらに件数集計のインデックス読み取り、閲覧者 1 件、表示ページの作成者（重複を除き最大 10 件）の取得が加わる（[Firestore の読み取り課金](https://firebase.google.com/docs/firestore/pricing)）。

検索時は最初の 10 件だけを対象に絞り込まない。DB の取得条件に合う候補が 300 件なら、キーワードなどの絞り込み後に 1 件になってもマシンは 300 件取得する。通常表示の 1 ページ目では同じ候補数でも最大 10 件だけ取得する。ページ移動・検索条件変更でサーバーの取得が再実行されると、それぞれのモードで読み直す。

数百件・少人数での初期運用では、検索時の全件取得を許容して既存の部分一致検索・回答状態の検索を維持する。応答時間は説明文のデータ量、通信状況、アクセス頻度にも依存する。データ増加時には検索用の索引、ユーザー別回答状態のデータ構造、カーソル方式のページ移動などを検討する。

### 導入・検証手順

1. `machines.created_at` が UTC・ミリ秒固定の文字列に統一されていることを確認する。古い形式のデータがある環境では、元の時刻を保ったまま `Date.toISOString()` 相当の形式に移行する。
2. フロントエンドのディレクトリで `firebase deploy --only firestore:indexes` を実行し、`firestore.indexes.json` を反映する。検索用の `published + status`、`created_by + status` に加え、通常一覧用にそれぞれ `created_at` の昇順／降順とドキュメント ID 昇順を含む複合インデックスを用意する。
3. すべてのインデックスが利用可能になってからアプリの変更を反映し、通常一覧の両方向の並び順・2 ページ目と検索を確認する。作成要求が成功しても構築中は `FAILED_PRECONDITION` が発生するため、構築完了まで待つ。

## 画面状態

| 状態 | 表示・操作 |
| --- | --- |
| 読み込み中 | 初回のルート読み込みは共通の読み込み表示。検索中は見出しと検索フォームを残し、「利用できるマシン」以下だけを Suspense で「読み込んでいます」に切り替える。 |
| 一覧あり | テーブル、件数、現在ページと前後ページの操作（1 ページの場合も表示）。 |
| 空 | 「マシンがありません。」のみ表示。 |
| 検索結果なし | 「マシンがありません。」のみ表示。 |
| 取得失敗 | エラー境界で失敗と再読み込みボタンを表示。内部エラーやフラグは表示しない。 |

## 検証

- 他人の公開マシンと自作の公開・非公開マシンを取得し、他人の非公開マシンと削除済みマシンは DB の取得結果に含まれないこと。
- `owned=1` では他人の公開マシンも DB の取得結果に含まれず、所有者のパス形式・UID 単体形式の両方で自作を取得できること。
- キーワードの名前・タグへの部分一致、大文字小文字、空文字、検索対象外のフィールド、複数条件の AND と難易度内の OR、ユーザー別の回答状態を確認すること。
- 日時順、同日時の ID 順、0 件・10 件・11 件のページ境界、最終ページへの補正、URL 条件保持、不正入力の扱いを確認すること。
- 通常一覧は DB から最大 10 件だけ取得し、検索時は先頭 10 件の外にあるマシンも検索結果に含まれること。
- インデックスの構築完了後、通常一覧と `owned=1` の両方のクエリが成功すること。
