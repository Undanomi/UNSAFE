# マシン一覧画面

## 基本情報

| 項目 | 内容 |
| --- | --- |
| 対応 Issue | #24（機能設計）、#34（DB 接続） |
| ルート | `/machines` |
| アクセス条件 | 認証必須。未認証の場合は `/login` へ遷移する。 |
| 目的 | 公開済みまたは自分が作成したマシンを探し、詳細表示または新規作成を開始する。 |

## 表示・操作

- テーブル形式で、マシン名、タグ、難易度、回答状態、作成者、作成日の列を表示する。マシン名の下に概要を補足表示する。
- 作成者の頭文字アイコン・名前、作成日（日本時間）を表示する。内部 ID は一覧に表示しない。
- 狭い画面ではテーブル部分を横スクロールして閲覧する。
- マシン名から `/machines/[machineId]`、作成者名から `/users/[userId]` へ遷移する。
- 「マシン作成」から `/machines/chat` へ遷移する。共通サイドバーにプロフィールへの導線を置く。
- キーワード、難易度、自分が作成したマシン、回答状態を組み合わせて検索する。
- 検索ボタンで条件を適用し、1 ページ目に戻る。条件リセットは並び順も初期値に戻す。
- 1 ページ 10 件。総件数と表示範囲を表示し、テーブル下には 1 ページだけの場合も現在ページと前後ページの操作を表示する。ページ番号は先頭・末尾・現在ページとその前後を表示し、離れた範囲は「…」で省略する。現在ページは黒背景・白文字、他ページは白背景の角丸枠とし、前後移動は矢印で表示する。移動できない方向は無効表示にする。0 件の場合はページネーションを表示しない。

## URL クエリ

| パラメーター | 値・既定値 |
| --- | --- |
| `page` | 1 始まりの整数。未指定・不正値・重複指定は 1。総ページ数を超える場合は最終ページへリダイレクトする。 |
| `q` | 前後空白を除いた最大 100 文字。マシン名・タグのいずれかに部分一致（英字は大文字小文字を区別しない）。 |
| `level` | `very_easy` / `easy` / `medium` / `hard` をチェックボックスで複数選択。`?level=very_easy&level=easy` のように URL に保持する。難易度同士は OR、他の条件とは AND。未選択（有効な値なし）はすべて。重複値は除去する。表示名は Very Easy / Easy / Medium / High。 |
| `owned` | `1` の場合は自分が作成したマシンのみ。それ以外は公開済みマシンと自分が作成したマシン。 |
| `solved` | `yes`（回答済み）/ `no`（未回答）。それ以外はすべて。 |
| `sort` | `desc`（新しい順、既定値）/ `asc`（古い順）。作成日時が同じ場合は ID 昇順で安定させる。 |

ページ移動時にすべての適用済み条件を保持する。URL の再訪問・再読み込み・ブラウザーの戻る／進むでも同じ条件を復元する。

## DB 契約と取得責務

- セッション Cookie を検証した利用者 ID をサーバーの一覧サービスへ渡す。クライアントから所有者 ID を受け付けない。
- PostgreSQLの `machines` は `status in [created, building, ready, failed, cancelled, preparing]` かつ、通常は `published = true` または自分が作成したものを取得する。「自分が作成したマシンのみ」を指定した場合は自作だけを取得する。
- `machines.id` を正とし、`status = deleted` はDBクエリで除外する。
- 一覧取得では `name`, `description`, `tags`, `level`, `created_at`, `created_by`, `published`, `status` だけを取得する。フラグ正解値・成果物パス・AI セッション ID は読み出さない。
- 回答済みは、そのマシンに存在する全フラグの正解履歴が `machine_flag_solutions` に揃った場合に `machine_solutions` へ記録する。自分が作成したマシンとフラグを持たないマシンは未回答として扱う。
- 不正解や空回答は記録せず、正解時は複合主キーでフラグごとの履歴とマシンの完了履歴を冪等に保存する。
- 作成者は `users` と結合して取得する。
- 一覧から移動した詳細が同名 ID のダミーデータにならないよう、詳細取得も DB を正とする。

### ページングの実現方法と制約

検索・絞り込み・回答状態・日時順の整列・総件数・10件単位のページングをPostgreSQL側で処理する。日時は `timestamptz` に統一し、ページ番号が総ページ数を超えた場合は最終ページを返す。

## 画面状態

| 状態 | 表示・操作 |
| --- | --- |
| 読み込み中 | 初回のルート読み込みは共通の読み込み表示。検索中は見出しと検索フォームを残し、「利用できるマシン」以下だけを Suspense で「読み込んでいます」に切り替える。 |
| 一覧あり | テーブル、件数、現在ページと前後ページの操作（1 ページの場合も表示）。 |
| 空 | 「マシンがありません。」のみ表示。 |
| 検索結果なし | 「マシンがありません。」のみ表示。 |
| 取得失敗 | 共通のエラー表示を使用する。内部エラーやフラグは表示しない。 |

## 検証

公開済みまたは自作の取得、自作の非公開マシンの取得、他ユーザーの非公開マシンの除外、削除済み除外、複合条件、タグ検索、日時順、ページ境界、URL 条件保持、不正入力の扱いを検証する。
